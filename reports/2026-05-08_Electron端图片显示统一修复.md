# 执行报告：Electron 端图片 fallback 路径统一修复

## 任务摘要

用户反馈 Electron 桌面端首页 "私有歌单" 区块的歌单封面仍显示为破图占位符。前置报告 `2026-05-08_Electron端图片显示修复.md` 已修复 `Playlist/index.vue` 与 `PrivatePlaylists.vue`，但其遗留问题中明确列出："项目中其他页面（如 SongList.vue、PlaylistGrid.vue 等）仍使用硬编码 `'/images/logo/favicon.png'` 作为 fallback，在 Electron 端可能存在同样的问题"。本次为该遗留项的全量收口。

**根本原因：** Electron 生产构建中前端以 `file://` 协议加载，绝对路径 `/images/logo/favicon.png` 会被解析到文件系统根目录而非应用资源目录，从而导致 fallback 图片永远加载失败。当 `:src` 的链式 `||` 兜底值与 `fallback-src` 都使用该路径时，浏览器没有任何可恢复的图源 → 显示破图。

**修复方案：** 将所有 fallback 路径替换为 Vite 静态资源导入 `import fallbackCoverUrl from "/images/logo/favicon.png"`，由 Vite 在构建时把它解析为最终打包后的相对资源路径，在 `http://`、`file://` 两种协议下都能被浏览器正确解析。

## 关键变更说明

### 1. 模板替换模式（`n-image` / `n-avatar`）

```diff
- :src="resolveXxxUrl(...) || '/images/logo/favicon.png'"
- fallback-src="/images/logo/favicon.png"
+ :src="resolveXxxUrl(...) || fallbackCoverUrl"
+ :fallback-src="fallbackCoverUrl"
```

注意：
- `fallback-src` 必须改成 `:fallback-src` 绑定，否则 Vue 会把字符串字面量 `"fallbackCoverUrl"` 当作图片路径而非变量引用。
- `:src` 中的链式 `||` 表达式继续保留（仍优先尝试真实封面），仅最末端的兜底值替换。

### 2. 渲染函数替换模式（`h(NImage, {...})` / `h('img', {...})`）

```diff
- src: ... ? resolveCoverUrl(...) : ... : '/images/logo/favicon.png'
+ src: ... ? resolveCoverUrl(...) : ... : fallbackCoverUrl

- fallbackSrc: '/images/logo/favicon.png'
+ fallbackSrc: fallbackCoverUrl

- onError: (e) => { target.src = '/images/logo/favicon.png'; }
+ onError: (e) => { target.src = fallbackCoverUrl; }
```

### 3. 导入语句（7 个文件新增，PlaylistGrid 已存在）

```ts
import fallbackCoverUrl from "/images/logo/favicon.png";
```

Vite 会把该 import 解析为构建后产物中的实际 URL（带 hash 文件名），在两种协议下都可被 `<img>` 元素解析。

### 4. 受影响的视觉区块

| 区块 | 触发场景 |
|------|---------|
| 首页 / 收藏歌单页的歌单卡片（桌面视图） | 歌单无封面或封面 URL 解析失败 |
| 专辑详情页头部封面 | 专辑无封面 |
| 艺术家详情页头部封面 | 艺术家无封面 |
| 播放历史页：用户头像 + 表格封面列 | 用户无头像 / 历史项无封面 |
| 我喜欢的歌曲页：用户头像 | 用户无头像 |
| 收藏的歌单页：用户头像 | 用户无头像 |
| 歌曲列表（缩略图模式）封面 | 歌曲无封面 |
| 后台歌曲管理页表格封面列 | 加载失败时的 onError 兜底 |

## 遗留问题

1. **未处理的 Logo 元素：** `src/views/Init/index.vue:19` 与 `src/components/DataModel/AboutSite.vue:14` 仍使用 `<img src="/images/logo/favicon.png">`，但它们承担的是 "应用 Logo" 角色而非 fallback 角色（前者为登录前初始化页，后者为关于弹窗）。如果 Electron 端这两处也观察到破图，需另起任务以 `import` 方式替换。

2. **`SongList.vue` 中的 `getCoverSrc` 兜底值：** 该函数 L287 末端 `return "/images/logo/logo.png"` 使用的是 **`logo.png`** 而非 `favicon.png`，且仅在 `coverUrl + album?.picUrl + picUrl + id` 全部缺失时触发（极罕见场景）。本次未一并替换以保持原始视觉语义；如需统一，建议另行评估是改用 `fallbackCoverUrl`（favicon）还是新增 `import fallbackLogoUrl from "/images/logo/logo.png"`。

3. **后端 `prompts/prompt_*.md` 找不到的错误日志：** 用户提供的日志截图（2026-05-08 21:56）仍出现 `open prompts\prompt_playlist1.md: The system cannot find the path specified.` 这与今日早些时候 `2026-05-08_提示词文件相对路径修复.md` 报告中的 `prompt.Read` 修复对应。可能的原因是后端服务仍在运行旧 binary（修复前编译的 `server.exe`），需要重启使用最新构建产物。该问题与本次前端修复独立，建议单独排查。

4. **未处理的图片 fallback 范围：** 本次仅覆盖 `'/images/logo/favicon.png'` 字面量。如果项目其他位置（如新增组件或其他模块）继续以硬编码绝对路径作为 fallback，在 Electron 端会复现同类问题。建议后续以 ESLint/grep 规则禁用 `'/images/...'` 字面量在 `:src` / `fallback-src` / `onError` 中的使用。
