# 执行报告：Electron 端私有歌单封面显示修复

## 任务摘要

修复 Electron 桌面端私有歌单列表中歌单封面显示错误的问题。

**根因**：Vite 默认 `base` 为 `/`，导致构建后通过 `import` 导入的静态资源（如 `fallbackCoverUrl`）生成绝对路径 `/images/logo/favicon.png`。Electron 生产环境以 `file://` 协议加载前端资源，该绝对路径被解析为文件系统根目录，导致 fallback 图片无法加载，显示为破损图标。

**影响范围**：所有使用 `import` 导入的静态资源（图片、JS、CSS 等）在 Electron 生产环境下均可能因绝对路径而加载失败。

## 修改文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/components/DataList/PlaylistGrid.vue` | 修改 | 引入 Vite 静态资源导入 `fallbackCoverUrl`，替换 6 处硬编码 fallback 路径 |
| `vite.config.ts` | 修改 | 新增 `base: "./"`，使构建后的资源路径变为相对路径，兼容 Electron `file://` 协议 |

## 关键变更说明

### 1. `vite.config.ts`：设置相对路径 base

```ts
return defineConfig({
  base: "./",
  plugins: [...]
})
```

- Vite 默认 `base` 为 `/`，构建后所有资源引用使用绝对路径（如 `/assets/index-xxx.js`、`/images/logo/favicon.png`）。
- 在 Electron `file://` 协议下，绝对路径 `/xxx` 被解析为 `file:///xxx`（文件系统根目录），导致资源加载失败。
- 设置 `base: "./"` 后，资源路径变为相对路径（如 `./assets/index-xxx.js`、`./images/logo/favicon.png`），从 `index.html` 所在目录解析，在 `file://` 和 `http://` 环境下均能正确加载。

### 2. `src/components/DataList/PlaylistGrid.vue`：替换硬编码 fallback 路径

- 引入静态资源导入：
  ```ts
  import fallbackCoverUrl from "/images/logo/favicon.png";
  ```
- 替换 6 处硬编码路径：
  - 移动端列表封面 `n-image` 的 `:src` fallback 与 `:fallback-src`
  - 桌面端网格封面 `n-image` 的 `:src` fallback 与 `:fallback-src`
  - 右键菜单头部 `renderMenuHeader` 中 `NImage` 的 `src` 与 `fallbackSrc`

## 验证结果

- **前端 TypeScript 检查**：`npx vue-tsc --noEmit` 通过，无类型错误。

## 注意事项

- **必须重新构建 Electron 应用**：`vite.config.ts` 的修改仅在构建时生效，需要重新运行 `npm run build`（或 `npm run build:server` / `npm run build:client`）并重新打包 Electron 才能看到修复效果。

## 遗留问题

- 项目中其他页面（如 `SongList.vue` 等）仍可能使用硬编码 `'/images/logo/favicon.png'` 作为 fallback。虽然 `base: "./"` 已解决 Electron 端绝对路径问题，但建议后续统一排查并使用 `fallbackCoverUrl` 导入方式，确保代码一致性。
