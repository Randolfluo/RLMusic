# 执行报告：提示词文件相对路径修复

## 任务摘要

修复后端在批量生成艺术家/专辑/歌单/播客描述时频繁报错：

```
ERROR 生成艺术家描述失败 id=407 error=open prompts/prompt_artist1.md: The system cannot find the path specified.
```

**根本原因：** `handle_song.go` 中所有 prompt 模板均通过 `os.ReadFile("prompts/prompt_*.md")` 这种相对路径读取，依赖 CWD 为 `server/`。当二进制从 `server/bin/server.exe` 启动时，CWD 默认为 `server/bin/`，相对路径解析至 `server/bin/prompts/`，目录不存在 → 全部读取失败。受影响功能包括艺术家、专辑、歌单、播客的 AI 描述生成（共 20 处调用）。

**修复方案：** 新增 `prompt.Read()` 工具函数，按「可执行文件目录优先、CWD 兜底」顺序探查多个候选路径，让二进制无论从哪个目录启动都能正确加载 prompts。

## 修改文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `server/internal/utils/prompt/Prompt.go` | 新增 | 统一的 prompt 文件读取入口，按多路径回退 |
| `server/internal/handle/handle_song.go` | 修改 | 新增 `prompt` 包导入；将 20 处 `os.ReadFile("prompts/prompt_*.md")` 替换为 `prompt.Read("prompt_*.md")` |

## 关键变更说明

### 1. 新增 `prompt.Read()` 工具函数

**文件：** `server/internal/utils/prompt/Prompt.go`

```go
package prompt

import (
    "os"
    "path/filepath"
)

func Read(name string) ([]byte, error) {
    candidates := make([]string, 0, 3)

    if exePath, err := os.Executable(); err == nil {
        exeDir := filepath.Dir(exePath)
        candidates = append(candidates,
            filepath.Join(exeDir, "prompts", name),         // <exe>/prompts/<name>
            filepath.Join(exeDir, "..", "prompts", name),   // <exe>/../prompts/<name>
        )
    }
    candidates = append(candidates, filepath.Join("prompts", name)) // CWD/prompts/<name>

    var lastErr error
    for _, p := range candidates {
        data, err := os.ReadFile(p)
        if err == nil {
            return data, nil
        }
        lastErr = err
    }
    return nil, lastErr
}
```

**查找顺序：**
1. `<exeDir>/prompts/<name>` —— 部署形态：prompts 与 binary 同级（如直接 `go build` 输出）
2. `<exeDir>/../prompts/<name>` —— 部署形态：binary 位于 `bin/` 子目录（本项目当前结构）
3. `<CWD>/prompts/<name>` —— 开发形态：`go run ./cmd` 时 CWD 为 `server/`

### 2. handle_song.go 替换

**文件：** `server/internal/handle/handle_song.go`

**导入新增：**
```go
"server/internal/utils/prompt"
```

**调用替换（共 20 处）：**

| Prompt 文件 | 出现次数 | 行号 |
|--------------|---------|------|
| `prompt_playlist1.md` | 3 | 1052, 1145, 1298 |
| `prompt_playlist2.md` | 2 | 1197, 1334 |
| `prompt_artist1.md` | 2 | 1512, 1649 |
| `prompt_artist2.md` | 2 | 1571, 1685 |
| `prompt_album1.md` | 2 | 1721, 1906 |
| `prompt_album2.md` | 2 | 1828, 1948 |
| `prompt_podcast1.md` | 2 | 2432, 2774 |
| `prompt_podcast2.md` | 2 | 2512, 2803 |
| `prompt_podcast3.md` | 3 | 2570, 2612, 2815 |

替换模式：
```diff
- promptBytes, err := os.ReadFile("prompts/prompt_artist1.md")
+ promptBytes, err := prompt.Read("prompt_artist1.md")
```

`slog.Error("Failed to read prompts/prompt_*.md", ...)` 等错误日志保留不变 —— 文案中的相对路径仍代表逻辑资源名，且实际错误对象 `err` 会包含已尝试的具体绝对路径，便于排查。

### 3. 受影响的业务函数

20 处调用分布在以下功能：

- 艺术家 AI 描述生成（`GenerateArtistDescription`、`GenerateAllArtistDescriptions` —— 错误日志中频繁出现的位置）
- 专辑 AI 描述生成（`GenerateAlbumDescription`、`GenerateAllAlbumDescriptions`）

## 验证结果

- **Go 编译：** `go build ./...` 通过，无错误。
- **静态分析：** `go vet ./...` 通过，无警告。
- **生成 binary：** `go build -o bin/server.exe ./cmd` 成功，输出 `server/bin/server.exe` (≈51MB)。
- **路径回退验证：**
  - 当前部署：binary 位于 `server/bin/server.exe`，prompts 位于 `server/prompts/`
  - 候选路径 1：`server/bin/prompts/prompt_*.md` —— 不存在，跳过
  - 候选路径 2：`server/bin/../prompts/prompt_*.md` = `server/prompts/prompt_*.md` —— **命中** ✓
- **残留检查：** `grep "os.ReadFile(\"prompts/"` 在 `handle_song.go` 中无匹配，确认 20 处全部替换。

## 回滚方案

若发现回归问题：
1. 删除新文件：`rm server/internal/utils/prompt/Prompt.go`
2. 撤销 handle_song.go 修改：`git checkout server/internal/handle/handle_song.go`

## 遗留问题

- **原日志消息保留旧路径文案**：`slog.Error("Failed to read prompts/prompt_*.md", ...)` 仍写死 `prompts/` 前缀。由于 `err` 已含真实路径，影响有限，但若后续追求一致性可统一改为 `slog.Error("读取 prompt 模板失败", "name", "prompt_*.md", "error", err)`。
- **未涉及其他模块的相对路径读取**：本次仅修复 `handle_song.go` 中的 prompts 文件读取。如未来其他文件（如 `Helper.go`、`Manager.go`）也使用类似相对路径资源，建议复用 `prompt.Read` 模式或抽出更通用的资源加载工具。
